# Автоматическое обновление Timeweb

После активации: push в `main` → GitHub собирает Docker-образ → передаёт
образ по SSH → сервер запускает свободный слот → проверяет приложение и
`SELECT 1` в PostgreSQL → nginx переключает upstream. Ошибка до переключения
сохраняет старый сайт; ошибка проверки после переключения восстанавливает
предыдущую конфигурацию. Миграции БД автоматически не выполняются.

## Настройки GitHub

Секреты Actions:
- `TIMEWEB_DEPLOY_KEY`: отдельный приватный ключ только для выкладки.
- `TIMEWEB_KNOWN_HOSTS`: проверенный ключ сервера (не слепой ssh-keyscan в CI).
- `TIMEWEB_PUBLIC_ENV`: однострочные `NEXT_PUBLIC_*=value` для сборки браузера.

Переменные Actions:
- `TIMEWEB_HOST=94.198.217.44`.
- `TIMEWEB_DEPLOY_ENABLED=true` — включить только после первой миграции.

Изменения веток и pull request проходят сборку без выкладки. Частный
runtime.env не передаётся в GitHub и Docker-образ. База, почта, сессии,
Bitrix и другие рабочие секреты находятся только в
`/opt/edinayasreda/runtime.env` (root, 600), формат Docker env-file.
Многострочные значения PEM передавать с буквальными `\n`, без кавычек
вокруг значения. Сохранить действующие секреты сессий и шифрования.

## Первая установка (оператор)

1. Создать каталог `/opt/edinayasreda` с правами 700.
2. Установить `deploy.sh` как `/usr/local/sbin/edinayasreda-deploy`, root:root 755.
3. Создать сеть `edinayasreda-runtime`, подключить к ней `vercel-proxy`.
   Это подключение также внести в исходный compose прокси, чтобы сохранить
   при его пересоздании. Не занимать вторым прокси порты 80/443.
4. Добавить отдельный ключ CI в root authorized_keys с ограничениями:
   `restrict,command="/usr/local/sbin/edinayasreda-deploy" ssh-ed25519 …`.
   CI не получает интерактивный shell или возможность менять секреты.
5. Подготовить runtime.env, сертификат домена и отдельный nginx vhost
   с `proxy_pass http://edinayasreda_web`, корректными Host,
   X-Forwarded-Proto, X-Forwarded-For. Кабинеты/API не кешировать.
6. Для первого кандидата не подключать публичный vhost: сначала создать
   `/opt/edinayasreda/activated`, включить переменную GitHub и проверить
   кандидата. Не запускать фоновые публикации/рассылки на второй площадке.
7. После проверки кандидата подключить vhost и переключить домен; отдельно
   перенести Vercel Cron и внешний планировщик без двойного выполнения.

Скрипт не меняет DNS и сам не создаёт публичный vhost. До появления
runtime.env и файла activated выкладка запрещена. Основной сайт остаётся
на Vercel до завершения первой миграции.

## Откат

Сервер хранит текущий и предыдущий SHA в `/opt/edinayasreda`. Из
административной SSH-сессии выполнить:

```bash
/usr/local/sbin/edinayasreda-deploy "rollback $(cat /opt/edinayasreda/previous-sha)"
```

Откат использует уже загруженный образ, проходит те же проверки. Он не
откатывает записи/структуру БД. Не применять глобальный `docker system prune`:
на сервере есть чужие сервисы. Контролировать накопление собственных образов;
перед выкладкой требуется минимум 5 ГБ свободного места.

Лимит каждого web-контейнера 3 ГБ RAM / 2 CPU. На время обновления
работают два слота. Проверить совместную нагрузку с речевыми сервисами до
переключения production. Остановить старый слот после завершения активных
запросов, если не нужен горячий резерв.
