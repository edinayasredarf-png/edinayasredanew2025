# Content OS — PHASE 1: интеграции

По §50 ТЗ: для Telegram/VK/MAX/Dzen/email-провайдера/поиска — не
придумывать API. Где официальный API неизвестен или недоступен —
интерфейс + мок, не фиктивная реализация.

## 1. LLM — уже есть, не интеграция, а переиспользование

Покрыто в `architecture.md` §2 (AI Gateway). Здесь только фиксирую: **не
заводить новый `@anthropic-ai/sdk` вызов нигде в Content OS напрямую** —
только через `getContentOsProvider(task)` (router) → существующие
`AnthropicProvider`/`YandexGptProvider`/`OpenAiCompatProvider`.

## 2. Источники (Topic Hunter) — расширение радара

Уже реализовано и в проде (audit.md §7, §14a):
- `keyword` (Google News RSS-поиск по фразе);
- `rss` (прямая RSS-лента + фильтрация по ключевым словам);
- `telegram` (открытый веб-просмотр `t.me/s/<канал>`, без токена — добавлено
  в этой сессии).

**Открытый вопрос для настоящего масштабирования Telegram-мониторинга**
(допущение №10 в architecture.md): веб-просмотр `t.me/s/` отдаёт только
~20 последних постов на странице каждого канала при каждом опросе — при
опросе раз в час этого достаточно для большинства каналов (посты выходят
реже, чем раз в 3 минуты), но не годится для «наверстать» после простоя
дольше нескольких часов, и не работает для приватных/закрытых каналов.
Найденный в Downloads `telegram_monitor.py` (Telethon, настоящий API-логин
`api_id`/`api_hash`) снимает оба ограничения. Решение о переносе на
Telethon — на новом VPS (не на Vercel — Telethon держит постоянную сессию,
это process, не serverless-вызов), как отдельный контейнер
`telegram-monitor` (см. infrastructure.md §2). Требует от владельца
`TELEGRAM_API_ID`/`TELEGRAM_API_HASH` (my.telegram.org) и логин обычного
Telegram-аккаунта для сессии.

**Веб-поиск для Research Engine (§22, §77 ТЗ)** — в проекте сейчас нет
интеграции с поисковым API. Варианты (решить в Phase 4, не блокирует
Phase 1):
- встроенный web-search инструмент Anthropic API (если доступен на
  используемом тарифе — самый простой путь, не плодит нового провайдера);
- отдельный провайдер (Brave Search API, есть бесплатный тир; или Google
  Custom Search JSON API).
Пока не выбрано — `ResearchEngine` пишется с интерфейсом `SearchProvider`
и **мок-реализацией**, которая явно возвращает «поиск не настроен» вместо
тихого молчания.

## 3. Публикация — ни одного канала не готово, у всех адаптер + мок

| Канал | Что есть сейчас | Что нужно для реальной публикации | Статус адаптера |
|---|---|---|---|
| Сайт (ARTICLE) | Полноценный `blogStore`/`dataDb.ts` — публикация статьи уже работает (это существующий блог сайта) | Ничего — переиспользуем как есть | Готов, не мок |
| Telegram | Только чтение (`t.me/s/`) | Bot API token (@BotFather) + id канала/чата для публикации — **отдельно** от Telethon-аккаунта для чтения (§ТЗ п.6 ROADMAP заготовки) | Интерфейс + мок |
| VK | Только чтение статистики (`VK_STATS_TOKEN`, scope `stats`) | Токен сообщества со scope `wall`,`manage` (новый токен, не переиспользовать read-only) | Интерфейс + мок |
| MAX | Ничего | Официальный API для публикации не подтверждён на момент этого аудита (dev.max.ru описывает создание ботов/сценариев, не нашёл документированного простого «опубликовать пост в канал» без дополнительной проверки) | Интерфейс + мок, подтвердить API отдельно перед Phase 11 |
| Дзен | Ничего (только ссылка в футере) | Официального публичного API публикации не нашёл при поиске ранее в этом чате | Интерфейс + мок |
| Email | — | `[ОТЛОЖЕНО]` | — |

```ts
// src/lib/server/contentOs/publishing/interfaces.ts
export interface ChannelPublisher {
  readonly channel: string;
  publish(item: ContentItemForPublish): Promise<{ externalId?: string; url?: string }>;
  isConfigured(): boolean;   // false → UI показывает "экспорт для ручной публикации" вместо кнопки "Опубликовать"
}
```

**Явное решение для MVP:** пока токен канала не настроен,
`ChannelPublisher.isConfigured() === false` → админка предлагает
«Скопировать готовый текст» вместо автопубликации. Это не блокирует
производство контента отсутствием токенов (audit.md, риск №5) — контент
готовится и утверждается, публикация — вручную, пока адаптер не подключён.

## 4. Email `[ОТЛОЖЕНО]`

Транзакционная инфраструктура уже есть (`src/lib/server/mailer.ts`,
SMTP через домен Timeweb) — **не годится напрямую** для кампаний без
дополнительного слоя (список получателей, отписка, репутация домена, см.
audit.md риск №6). Когда вернёмся к email — здесь появится `EmailProvider`
интерфейс (§9 ТЗ) и решение по конкретному провайдеру после разговора с
владельцем (не выбираю сейчас).
