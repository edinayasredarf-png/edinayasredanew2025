# Postmill ↔ ЕдинаяСреда — аудит интеграции

Задача на вход: взять open-source **Postmill** (`postmill-ai/postmill-app`,
https://github.com/postmill-ai/postmill-app) как фундамент для Content OS
и адаптировать его под существующий проект ЕдинаяСреда, максимально
переиспользуя готовый код.

Это аудит, не решение и не код. Ниже — факты о двух системах и где они
расходятся. Источники: сам репозиторий Postmill (README, структура
монорепо), его сайт postmill.ai, и код/документы текущего проекта
(`docs/content-os/*`, `package.json`, `supabase/migrations/*`, память
сессии от 2026-09-28/29).

## 0. Важная поправка к вводным

«Postmill» в задаче — **не** классический форумный Postmill (PHP/Symfony,
Reddit-подобная доска, существует с 2018 г.). Репозиторий
`postmill-ai/postmill-app` реальный, но это **другой, новый продукт**:
self-hosted SMM-платформа (планировщик публикаций для 45+ соцканалов,
AI-композер, дизайнер, аналитика) под AGPL-3.0, от другой команды. Это не
ошибка в задаче — репозиторий существует и соответствует описанию в
промпте (календарь, Brand Voice, RAG, approvals) — но важно знать, что это
**не** древний форумный движок, который можно было бы перепутать по имени.

## 1. Сравнительная таблица

| Component | Postmill (`postmill-ai/postmill-app`) | ЕдинаяСреда (текущий проект) | Решение |
|---|---|---|---|
| **Frontend** | Next.js (App Router) — отдельное приложение в монорепо (`apps/`) | Next.js 15.4.8 App Router, React 19 — тот же фреймворк, но один монолит, не монорепо | **REPLACE не нужен, но не REUSE напрямую** — фреймворк совпадает случайно, код Postmill написан для его собственного бэкенда (NestJS API), не для прямых SQL-запросов текущего проекта |
| **Backend** | **NestJS**, отдельный сервис, REST + OpenAPI + SDK | Next.js API routes (`/api/*`), без отдельного бэкенд-фреймворка | **REPLACE нежелателен** — означало бы поднимать второй рантайм (NestJS) рядом с Next.js только ради одного модуля |
| **Database** | PostgreSQL, **своя схема**, которой владеет Prisma (миграции Prisma) | Timeweb Cloud PostgreSQL, прямой SQL через `pg`, без ORM, `create table if not exists` в коде | **REPLACE нежелателен.** Даже если физически использовать тот же Postgres-инстанс, Prisma потребует отдельную схему/БД под своим контролем миграций — это не «интеграция в существующую БД», а вторая БД рядом |
| **ORM** | Prisma | Нет (raw SQL, паттерн `timewebPg.ts`) | **REPLACE не нужен** — вводить Prisma только под один модуль создаёт два способа работы с БД в одном проекте |
| **Authentication** | Своя: Google/GitHub/Apple/Facebook/X/LinkedIn/OIDC OAuth + сессии с device revocation, всё через Prisma-таблицы Postmill | Своя cookie-сессия (`userSession.ts`/`editorSession.ts`, bcrypt), не завязана на внешние OAuth для прав в админке | **REPLACE невозможен без нарушения §3 ТЗ** («не создавать параллельную систему пользователей») — у Postmill юзеры/орги живут в его собственных таблицах. Встроить его как есть = завести вторую систему пользователей |
| **Authorization** | RBAC: 5 ролей + каталог 90 прав (18 ресурсов × 5 действий) — зрелая, гранулярная модель | Одна строка `user_profiles.role` (`admin/author/user` + отдельно `admin/rop/manager/analyst` для AI Sales) | **EXTEND (идея, не код)** — каталог прав Postmill можно взять как референс для будущего расширения ролей Content OS, если понадобится более гранулярный approval-флоу, чем «admin/редактор» |
| **API** | REST + OpenAPI spec + официальный Node SDK + MCP-поверхность для AI-агентов | REST `/api/*`, без OpenAPI/SDK | **EXTEND позже, не сейчас** — OpenAPI-описание уже имеющихся `/api/content-os/*` можно добавить независимо от Postmill |
| **AI architecture** | BYOK, 30+ провайдеров (17 прямых + 13 шлюзов/хабов), guardrails (prompt-injection/PII/NSFW), спенд-кэпы с аудит-логом | Своя абстракция `AiProvider` (`generateStructured`) — `AnthropicProvider`, `YandexGptProvider`, `OpenAiCompatProvider` (последний уже явно расчитан на «облачный OpenAI-совместимый шлюз, напр. Timeweb AI Gateway», и на self-hosted модели) | **REUSE существующей абстракции + EXTEND** — она уже «provider-agnostic» ровно в духе Postmill, не нужно переносить его AI-слой. Timeweb AI Gateway подключается как ещё один `OpenAiCompatProvider` (см. §3 ниже) |
| **RAG** | «Retrieval-augmented search over your own content» — детали реализации (chunking/вектора) в открытых источниках не раскрыты подробно | Работающий в проде паттерн без pgvector: чанки + эмбеддинги (Yandex, 256 изм.) в `jsonb`, косинус считается в коде (`ai_kb_documents/_chunks`, AI Sales). Для Content OS спроектированы параллельные `content_brand_documents/_chunks` (см. `docs/content-os/database.md` §5) | **REUSE существующего паттерна**, не ждать и не копировать RAG Postmill — чужая реализация недоступна для переноса (отдельная БД/бэкенд), а своя уже проверена в продакшене |
| **Content calendar** | Визуальный календарь (месяц/неделя/день), drag-to-reschedule, таймзоны, CSV-импорт | Спроектирован `content_clusters/content_items` + статусы (`draft→review→approved→scheduled→published`), `ContentPlanTab.tsx` в админке | **EXTEND существующий дизайн** — идея drag-to-reschedule/таймзон стоит взять в UI-требования следующей итерации `ContentPlanTab.tsx`, но это доработка своего компонента, не перенос чужого |
| **Publishing** | Автопубликация в 45+ каналов «из коробки», retry-логика, идемпотентность | Таблица `content_publications` с идемпотентностью спроектирована (`database.md` §6), но **реальных токенов публикации нет ни в один канал** (Telegram Bot API/VK wall/MAX/Дзен) — это уже было открытым вопросом аудита Content OS от 2026-09-28 | **ADAPT паттерн, не код** — у Postmill 45 готовых адаптеров каналов, но его публикационный пайплайн неотделим от его бэкенда/БД. | **Brand system** | Brand Kit: цвета/логотип/шрифты/референс-изображения, по-канальные инструкции — **вводятся вручную пользователем**, признаков AI-экстракции из загруженного PDF-брендбука в открытых описаниях нет | `content_brand_documents/_chunks` спроектированы под произвольные текстовые документы бренда + RAG | **Postmill не закрывает ключевое требование §7 промпта** (авто-извлечение цветов/шрифтов/правил из PDF/DOCX брендбука с ручной коррекцией) — это нужно проектировать самим в любом случае, Postmill тут не фундамент |

## 2. Критический блокер: лицензия AGPL-3.0

Postmill распространяется под **AGPL-3.0**. Это copyleft-лицензия с «сетевым»
условием (network use clause, §13 AGPL): если взять его код, изменить и
**запускать как сервис, доступный пользователям по сети** (ровно наш
случай — админка единаясреда.рф), нужно предоставлять полный исходный код
изменённой версии всем, кто взаимодействует с сервисом по сети — не только
при распространении бинарников.

Это не техническая, а юридическая/бизнес-развилка, которую нельзя решить
молча при адаптации кода:
- Либо владелец сознательно соглашается открыть исходники Content OS
  (или всего проекта, если границу «производной работы» провести широко)
  под AGPL-совместимой лицензией;
- Либо код Postmill не копируется и не адаптируется буквально — используется
  только как **референс архитектурных решений** (как уже делалось с чужой
  n8n/Telethon-заготовкой в `docs/content-os/audit.md` §14a — «не готовый
  код для копирования, а референс»).

**Без этого решения адаптировать исходники Postmill нельзя** — не вопрос
усилий, а вопрос лицензионных обязательств перед всеми пользователями сайта.

## 3. Единственное отдельное предложение (вне ТЗ): Timeweb AI Gateway

Независимо от решения по Postmill — в коде уже есть готовая точка
расширения под это: `src/lib/ai/providers/openaiCompat.ts` явно спроектирован
под «облачный OpenAI-совместимый шлюз (Timeweb AI Gateway и т.п.)», и в
AI Sales уже есть похожая механика (список моделей шлюза в настройках,
см. `src/lib/server/aiSales/settingsDb.ts`). Подключить тот же шлюз к
Content OS — это **конфигурация существующего провайдера** (ENV + выбор
модели в Settings), а не перенос кода Postmill. Низкий риск, укладывается
в уже принятый паттерн `AiProvider`.

## 4. Итог по компонентам (REUSE / ADAPT / REPLACE / EXTEND)

| Компонент | Статус |
|---|---|
| Auth, роли, admin-layout | **REUSE** (существующие, без изменений) |
| База данных (Timeweb Postgres) | **REUSE** (одна БД, без Prisma/второй схемы) |
| AI-провайдеры | **REUSE** существующей абстракции, **EXTEND** добавлением Timeweb AI Gateway |
| RAG / Brand Knowledge | **REUSE** существующего jsonb-косинус паттерна |
| Content calendar / Content Hub / Publishing / Analytics UI | **REUSE** уже спроектированного и частично построенного `Content OS` (`docs/content-os/*`) — он уже закрывает структуру §4 промпта (Dashboard/Calendar/Ideas/Content/Brand/Media/Publications/Analytics/Settings) |
| Brand Brain (экстракция из брендбука) | **НОВОЕ**, не из Postmill — ни Postmill, ни текущий проект это не закрывают, проектировать с нуля (но осмысленно, не бездумно) |
| Код/рантайм Postmill (NestJS, Prisma, его БД, его auth) | **REPLACE не рассматривается** — структурно несовместим с «не отдельный сайт, не вторые пользователи» (§3–4 промпта), плюс AGPL-блокер (см. §2) |
| Архитектурные идеи Postmill (RBAC-каталог прав, daily-snapshot аналитика, idempotent publishing, UI-паттерны календаря) | **EXTEND как референс для дизайна**, не как код |

## 5. Главный вывод

Postmill — реальный, качественный проект, но он **спроектирован как
отдельный self-hosted продукт** (свой бэкенд, своя БД, своя система
пользователей), что прямо противоречит ключевым требованиям самого
промпта (§3: не плодить вторую систему пользователей; §4: не делать
отдельный сайт). Чтобы запустить Postmill, нужно поднять второе
приложение — это и есть «параллельная система», которую задача просит
не создавать.

При этом у проекта **уже есть** собственный, выросший из такого же
аудита, Content OS (`docs/content-os/`, сессия 2026-09-28/29): он уже
переиспользует существующую авторизацию, существующую БД, существующую
AI-абстракцию, встроен в существующую админку — то есть уже делает то,
что промпт просит добиться через Postmill, но без архитектурного
конфликта и без AGPL-риска.

**Рекомендация:** не брать код/рантайм Postmill за основу. Продолжать
уже начатый `Content OS` (см. `docs/content-os-implementation-plan.md`),
по возможности заимствуя отдельные *идеи* Postmill (не код) там, где они
улучшают уже спроектированные разделы, плюс подключить Timeweb AI Gateway
как дополнительного AI-провайдера (§3 выше) — это единственная часть
входного запроса, которая по-настоящему независима от решения про Postmill
и может быть сделана прямо сейчас.
