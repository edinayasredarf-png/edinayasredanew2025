# AI-брифы по лидам и «Отложенному спросу»

**Что делает.** По каждому новому лиду (и раз в неделю по открытым сделкам воронки «Отдел продаж»
на этапе «Отложенный спрос») собирает бриф: данные CRM Bitrix24 + свежие «информационные
триггеры» из интернета (новости, бюджеты/программы, закупки, пересечения с услугами, соседи).

**Поток.**
1. `drain` (cron-job.org) раз в час ставит `brief.scan` → `briefScan.ts`:
   новые лиды за 3 дня без брифа → `brief.lead`; сделки на этапе «Отложенный» (этап ищется
   по названию в справочнике стадий) → `brief.deal` (ключ идемпотентности — ISO-неделя).
2. `briefService.runBrief`: `gatherCrm` (crm.*.get, реквизиты, комментарии, активности, прошлые
   сделки компании) → **поиск** — AI-агент Timeweb с включённой опцией «Поиск в интернете»
   (`agentSearchChat`; у AI Gateway веб-поиска нет, 0,49 ₽/запрос) → **сборка брифа** моделью
   AI Gateway (`ai.model.brief`) из CRM + найденного → запись в `ai_briefs` → поле Bitrix → уведомление.
3. «Новое» = ссылка триггера не встречалась в прошлых брифах по этой сущности.
   Для лида уведомляем всегда, для отложенной сделки — только если есть новое.

**Куда пишет.** Поле лида `UF_CRM_1791289652`, поле сделки `UF_CRM_1791289910`
(env `BRIEF_LEAD_FIELD` / `BRIEF_DEAL_FIELD`). Уведомление — `im.notify.system.add`
ответственному и РОПам (`user_profiles.role = 'rop'` через `ai_managers.user_profile_id`).

**Нужно в окружении.** `SELFHOSTED_LLM_URL` (+ `SELFHOSTED_LLM_API_KEY`), `BRIEF_SEARCH_AGENT_URL` и `BRIEF_SEARCH_AGENT_KEY` (агент Timeweb с веб-поиском); у вебхука Bitrix права `crm` и `im`;
у БД — право на DDL (таблица создаётся при первом обращении, см. `supabase/migrations/timeweb_ai_briefs.sql`).

**Ограничение.** Vercel Hobby режет функцию на 60 с: на поиск отведено 28 с, на сборку брифа 25 с.
Если не укладывается — задача уйдёт на повтор (до 2 попыток) и в списке будет «ошибка».

## Личные сообщения в Bitrix от бота (Эко_бот)

- Рассылка идёт через `im.message.add` (личный диалог), при отказе — системное уведомление. Автор сообщения —
  владелец вебхука, поэтому нужен отдельный входящий вебхук под пользователем «Эко_бот» (id 1) с правами
  «Чат и уведомления» (im) и «Пользователи» (user): переменная `BITRIX_BOT_WEBHOOK_URL`. Без неё используется
  основной вебхук (автор — его владелец). Проверка автора: админ-действие `bitrix-whoami`; тест: `bot-test`.
- Менеджеру, который говорил с клиентом: после `call.analyze`, если в разборе есть `managerPerformance.exampleBetterResponse`,
  ставится задача `notify.coach` → сообщение «Разбор вашего звонка» с названием сделки, ссылкой и текстом
  «Как лучше было ответить». Только по звонкам младше `COACH_MAX_AGE_HOURS` (48 ч) — бэкфилл старых не рассылается.
  Выключатель: настройка `briefs.coachEnabled`.
- РОПу (настройка `briefs.ropBitrixUserIds`, сейчас Диана Родякина, Bitrix-ID 67): бриф по сделкам «Отложенный спрос»
  — только если есть триггеры (первый бриф) или новые триггеры (повторный). Новый лид — ответственному менеджеру и РОПу.
